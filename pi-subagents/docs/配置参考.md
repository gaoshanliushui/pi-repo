# 配置参考

`pi-subagents` 的配置分布在几处，按优先级（低 → 高）：

1. **内置默认值**（`src/shared/types.ts` 中各常量）
2. **全局 subagent 配置**：`~/.pi/agent/extensions/subagent/config.json`
3. **Pi 主配置**：`~/.pi/agent/settings.json` 与 `<project>/.pi/settings.json`
4. **Agent frontmatter**：`<scope>/agents/<name>.md`、`~/.pi/agent/agents/`、`<project>/.agents/`
5. **运行时覆盖**：`subagent` 工具参数、`agentOverrides` settings、`watchdog.configure`

## 全局 subagent 配置

文件：`~/.pi/agent/extensions/subagent/config.json`

读写逻辑见 `src/extension/config.ts`。结构：

```jsonc
{
  // 默认走后台（async）。false 时需要显式 async:true
  "asyncByDefault": false,

  // 强制顶层 subagent 走 async，不允许前台 chain
  "forceTopLevelAsync": false,

  // 子代理最大嵌套深度（每层 -1）
  "maxSubagentDepth": 1,

  // 每个 session 最多 spawn 多少个子代理
  "maxSubagentSpawnsPerSession": 50,

  // 自定义工具描述文件路径（≤ 50KB），或 "full" | "compact" | "custom"
  "toolDescriptionMode": "full",

  // wait 工具开关（也可 PI_SUBAGENT_WAIT_TOOL_ENABLED 环境变量）
  "waitTool": true,

  // 异步完成通知批量合并（短暂延迟后合并相似通知）
  "completionBatch": {
    "enabled": true,
    "debounceMs": 800,
    "maxWaitMs": 2000,
    "stragglerDebounceMs": 200,
    "stragglerMaxWaitMs": 500,
    "stragglerWindowMs": 1500
  },

  // 跨上下文 intercom 桥（子代理能 contact_supervisor）
  "intercomBridge": {
    "mode": "always",            // "always" | "fork-only" | "off"
    "instructionFile": "./intercom-bridge.md"
  },

  // 自定义 worktree 准备脚本
  "worktreeSetupHook": "./scripts/setup-worktree.mjs",

  // 默认子代理临时目录
  "defaultSessionDir": "~/.cache/pi-subagents/sessions",

  // 是否启用 schedule action
  "scheduledRuns": { "enabled": false },

  // chain 相关
  "chain": {
    "dynamicFanout": { "maxItems": 50 }
  },

  // 默认并行并发
  "parallel": { "concurrency": 4, "maxTasks": 20 }
}
```

完整 schema 在 `ExtensionConfig`（`src/shared/types.ts`）。

## Pi 主 settings.json

文件：`~/.pi/agent/settings.json` 或 `<project>/.pi/settings.json`（项目级覆盖用户级）。

```jsonc
{
  "subagents": {
    // 所有 builtin / package / user / project agent 的默认模型
    // （frontmatter 没显式 model 的那些）
    "defaultModel": "anthropic/claude-sonnet-4-5",

    // 关闭 builtin 默认 thinking（provider 不支持 thinking 后缀时）
    "disableThinking": false,

    // 按 agent 名精细覆盖
    "agentOverrides": {
      "reviewer": {
        "model": "anthropic/claude-sonnet-4",
        "thinking": "high",
        "fallbackModels": ["openai/gpt-5-mini"],
        "systemPrompt": "Custom reviewer prompt...",
        "systemPromptMode": "append",
        "tools": ["read", "grep", "find"],
        "skills": ["code-review"],
        "disabled": false
      }
    },

    // 可选 watchdog 配置
    "watchdog": {
      "main": {
        "model": "anthropic/claude-opus-4",
        "thinking": "high"
      },
      "children": {
        "enabled": false,
        "model": "anthropic/claude-sonnet-4",
        "thinking": "medium",
        "overrides": {
          "worker": { "enabled": true, "thinking": "low" }
        }
      },
      "lsp": {
        "enabled": true,
        "timeoutMs": 4000,
        "maxFiles": 50,
        "maxDiagnostics": 100
      },
      "agentEndTimeoutMs": 60000
    }
  }
}
```

> 项目级 settings 的 `agentOverrides` 合并到用户级之上（项目优先），同名字段项目级赢。

## Agent Frontmatter

子代理定义文件：`<scope>/agents/<name>.md`（YAML frontmatter + Markdown 系统提示）。

### 内置 frontmatter 字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `name` | string | agent 名（必须） |
| `description` | string | 一句话说明，列在 `list` 输出里 |
| `model` | string | 默认模型（`provider/id`，可带 `:thinking`） |
| `fallbackModels` | string[] | 主模型失败时的备选 |
| `thinking` | string \| false | 默认 thinking 等级 |
| `systemPromptMode` | `"append" \| "replace"` | 自定义 system prompt 是追加还是替换 |
| `systemPrompt` | string | 自定义系统提示文本（frontmatter 内） |
| `tools` | string[] | 允许的工具；`mcp:foo` 表示 foo MCP 工具直传 |
| `mcpDirectTools` | string[] | 同上但只用于直接 MCP 工具调用 |
| `skills` | string[] | 默认加载的 skill |
| `extensions` | string[] | 仅在该 agent 中加载的额外扩展 |
| `subagentOnlyExtensions` | string[] | 同上但只在被当子代理调用时加载 |
| `output` | string \| false | 默认输出文件路径 |
| `defaultReads` | string[] | 默认 reads |
| `defaultProgress` | boolean | 是否默认开 progress.md |
| `defaultContext` | `"fresh" \| "fork"` | 上下文继承默认 |
| `defaultAsync` | boolean | 是否默认 async |
| `defaultTimeoutMs` | integer | 默认超时 |
| `defaultTurnBudget` | object | `{ maxTurns, graceTurns? }` |
| `toolBudget` | object | 默认 `{ soft?, hard, block? }` |
| `interactive` | boolean | 是否需要交互（TUI） |
| `maxSubagentDepth` | integer | 该 agent 内部允许的最大嵌套深度 |
| `completionGuard` | boolean | 是否启用完成守卫（防止提前结束） |
| `memory` | object | `{ scope: "project"\|"user", path }` |
| `disabled` | boolean | 是否禁用（仅当 settings 引用时生效） |
| `package` | string | 包的元信息（创建自定义 agent 时） |

### Agent 解析优先级

`src/agents/agents.ts:128-139` 显式给出 precedence：

```
project > user > package > builtin
```

同名 agent 高优先级覆盖低优先级。`eject` 把 builtin/package 拷贝到 user/project 作为可编辑副本；`disable` 用 settings 覆盖隐藏；`reset` 删除覆盖恢复默认。

### Chain 文件

`<scope>/chains/<name>.md`，frontmatter 里 `name` + `description`，正文是 chain 定义（YAML 或 JSON）。`agents/agent-serializer.ts`、`agents/chain-serializer.ts` 负责解析。

## 子代理模型选择

### 选模型时的解析

1. 工具参数 `model`（最高）
2. `agentOverrides.<name>.model`（settings）
3. agent frontmatter `model`
4. `subagents.defaultModel`（settings）
5. `defaultModel`（settings）
6. 当前 session 模型

模型字符串匹配做了模糊化（`src/shared/model-info.ts`）：

- 分隔符变体：`anthropic/claude-sonnet-4`、`anthropic:claude-sonnet-4`、`anthropic.claude-sonnet-4` 等价
- id 变体：`claude-haiku-4.5` ↔ `claude-haiku-4-5`
- 大小写不敏感
- 可选日期戳：`claude-haiku-4-5-20251001` ↔ `claude-haiku-4-5`
- `provider/id` 精确匹配始终胜出；带 provider 的查询不会静默切换 provider
- 多 provider 同名 id 必须显式带 provider

### 备选模型

```jsonc
{
  "fallbackModels": ["openai/gpt-5-mini", "google/gemini-2.5-pro"]
}
```

主模型连续失败时按顺序回退，由 `runs/shared/model-fallback.ts` 处理。

## 验收（acceptance）

定义在 `src/runs/shared/acceptance.ts`。每个任务可声明验收等级：

| 等级 | 含义 |
|------|------|
| `auto`（默认） | 智能推断：根据任务是否改文件、是否有 verify 命令等自动选等级 |
| `none` | 不验收 |
| `attested` | 子代理声明它做到了（不验证） |
| `checked` | 子代理返回结构化报告，父会话检查 |
| `verified` | 跑配置的 shell 命令做硬校验（`verified` 必须有 verify 命令） |
| `reviewed` | 用 reviewer 类型的子代理做二次审视 |

### 配置示例

```jsonc
{
  "acceptance": {
    "level": "verified",
    "criteria": [
      { "id": "typecheck", "must": "TypeScript compiles", "severity": "required" },
      { "id": "lint", "must": "Lint passes", "evidence": ["commands-run"], "severity": "recommended" }
    ],
    "evidence": ["changed-files", "tests-added", "commands-run", "validation-output", "residual-risks"],
    "verify": [
      { "id": "typecheck", "command": "pnpm tsc --noEmit", "timeoutMs": 60000, "cwd": ".", "allowFailure": false },
      { "id": "test", "command": "pnpm test", "timeoutMs": 120000 }
    ],
    "review": { "agent": "reviewer", "focus": "correctness and tests", "required": true },
    "stopRules": ["Do not modify CI files"],
    "reason": "Mandatory pre-merge verification"
  }
}
```

详细语义见 `AcceptanceLedger`（`src/shared/types.ts:454-470`）。

## Budgets（turn / tool 预算）

### Turn budget

```jsonc
{ "maxTurns": 30, "graceTurns": 3 }
```

到达 `maxTurns` 时给子代理注入"请收尾"的提示；再过 `graceTurns` 个 turn 就 abort 并返回部分输出。详细见 `runs/shared/turn-budget.ts`。

### Tool budget

```jsonc
{ "soft": 30, "hard": 50, "block": ["edit", "write", "mcp:fs"] }
```

- `soft` 到达时给子代理提示
- `hard` 到达后 `block` 列表里的工具直接拒收，让子代理用只读工具收尾
- `"block": "*"` 表示所有工具全部 block

## Control（子代理注意力）

```jsonc
{
  "control": {
    "enabled": true,
    "needsAttentionAfterMs": 120000,
    "activeNoticeAfterMs": 240000,
    "activeNoticeAfterTurns": 50,
    "activeNoticeAfterTokens": 200000,
    "failedToolAttemptsBeforeAttention": 3,
    "notifyOn": ["active_long_running", "needs_attention"],
    "notifyChannels": ["event", "async", "intercom"]
  }
}
```

- `active_long_running`：跑了很久没停
- `needs_attention`：idle 超时 / 连续工具失败 / turn/token 阈值

控制事件通过 `subagents:control:event` 发回，渲染成 inline 通知，并能让父模型通过 `interrupt` / `resume` / `steer` 干预。

## Worktree 隔离

并行模式 + `worktree: true` 时：

1. 检查 git 状态必须 clean
2. 为每个并行任务 `git worktree add` 一个独立目录
3. 子代理在 worktree 内工作
4. 完成后可 `diffWorktrees()` 汇总差异，或让父模型决定如何 merge

钩子：`worktreeSetupHook` 指向一个脚本，在每个 worktree 创建后被调用，用于 `pnpm install` 之类。

```jsonc
{ "worktreeSetupHook": "./scripts/setup-worktree.mjs" }
```

脚本签名：`setupWorktree({ worktreePath, baseBranch, taskIndex, agent }) => Promise<void>`。

## Intercom 桥（子代理回呼父会话）

```jsonc
{
  "intercomBridge": {
    "mode": "always",                       // "always" | "fork-only" | "off"
    "instructionFile": "./intercom-bridge.md"
  }
}
```

开启后，`context: "fork"` 的子代理会被自动注入：

- `intercom` 工具：通用 intercom
- `contact_supervisor` 工具：用于决策阻塞 / 进度汇报 / 结构化访谈请求

子代理拿到一段指令（默认模板见 `src/intercom/intercom-bridge.ts:20-30`），告诉它：

- 不要把 inherited thread 当成对话继续
- 决策阻塞、进度更新用 `contact_supervisor`
- 不要用 intercom 走常规完成交接

`instructionFile` 可指向自定义指令文件，模板字符串 `{orchestratorTarget}` 会被替换成父会话的 intercom target。

## Watchdog（对抗性改动复审）

`src/watchdog/` 实现可选的 watchdog。

### 默认模型推荐

`recommendStrongWatchdogModel(ctx)`（`watchdog/model-selection.ts`）默认推荐：

- 主会话用 Opus 4.8 → watchdog 用 GPT 5.5:high
- 主会话用 GPT 5.5 → watchdog 用 Opus 4.8:high
- 默认推荐 Opus 4.8:high / GPT 5.5:high

### 触发时机

- 仅在 `agent_end` 边界
- 仅当本回合实际改了仓库文件（包含子代理的累积编辑）
- 跳过 `.pi-subagents/` 和 `tmp/` 下的产物
- 跳过多改→回滚的 diff
- 多次编辑在同回合内合并为一次 review

### 流程

1. 收集 changed files、git diff
2. 自动探测 `typescript-language-server`（project `node_modules/.bin` → PATH）
3. 跑 LSP 拉诊断（错误 → blocker，警告 → concern）
4. 调用 watchdog 模型复审
5. 输出 `concern` / `blocker` 警告

### 配置

通过 `subagent({ action: "watchdog.configure", ... })` 或 `/subagents-watchdog` 命令：

```
/subagents-watchdog on
/subagents-watchdog off
/subagents-watchdog model anthropic/claude-opus-4-8:high
/subagents-watchdog session model recommended     # 仅本 session
/subagents-watchdog model recommended             # 写到 settings.json
/subagents-watchdog recommend-model
/subagents-watchdog status
/subagents-watchdog check
```

`scope: "user"` / `"project"` 写持久化设置；默认 `"session"` 只在当前 Pi 会话内生效。

## Scheduled runs

```jsonc
{ "scheduledRuns": { "enabled": true } }
```

启用后可在 `subagent({ action: "schedule", agent, task, schedule: "+10m" })` 里延迟启动。

- `schedule: "+10m"` 相对当前时间
- `schedule: "2030-01-01T09:00:00Z"` 绝对 ISO 时间（带时区）
- `scheduleName` 显示名
- 计划好的 run 存在 `~/.pi/agent/sessions/<sid>/scheduled/<id>.json`
- 触发时变成普通 async run
- `schedule-list` / `schedule-status` / `schedule-cancel` 管理

## Profile（provider 模型快照）

`src/profiles/profiles.ts` 提供 provider/model profile 持久化：保存当前选择的 provider+model，方便在 Pi 跨 session 时复用子代理的默认模型选择。一般通过 `/subagents-models` 命令交互。

## 故障排查入口

- `subagent({ action: "doctor" })`：运行时路径、发现、intercom、permission system 状态
- `/subagents-watchdog status`：watchdog 配置、最近 review、LSP 状态
- 检查 `~/.pi/agent/sessions/<sid>/async/<runId>/status.json`：异步 run 状态
- 检查 `~/.pi/agent/sessions/<sid>/async/<runId>/events.jsonl`：嵌套事件
- 检查 `<chain_dir>`：链式运行的 progress.md 和 step outputs
- `cat result-watcher` 监听 `~/.pi/agent/sessions/*/async/*/output.log`
