# 架构与运行流程

> `pi-subagents` 是 `@earendil-works/pi-coding-agent` 的 extension。它通过 `pi` 包管理的 `pi.extensions` 字段（`package.json:44-54`）注册 `src/extension/index.ts`，由 Pi 在加载时调用 `registerSubagentExtension(pi)`。

## 主流程

### 0. 启动

`registerSubagentExtension` 在 Pi 加载扩展时调用（`src/extension/index.ts:241-661`），做这些事情：

1. **短路子进程**：如果 `PI_SUBAGENT_CHILD=1`，直接 return（避免在子代理进程里再加载 extension 自身）
2. **清理旧状态**：调用 `__piSubagentRuntimeCleanup`（全局存储），处理 reload 残留
3. **准备目录**：`RESULTS_DIR`、`ASYNC_DIR`、`cleanupOldChainDirs()`
4. **加载配置**：`loadConfig()` → `~/.pi/agent/extensions/subagent/config.json`
5. **初始化 watchdog、result watcher、async-job-tracker、supervisor channel、scheduled-run-manager**
6. **构建 executor**：`createSubagentExecutor(...)` 是核心执行入口（`runs/foreground/subagent-executor.ts:127-...`）
7. **注册 4 个 message renderer**：`subagent-notify`、`subagent-result`、`subagent-text-result`、`subagent-control-notice`
8. **注册工具**：`subagent` 和 `wait`
9. **注册斜杠命令**：`registerSlashCommands(pi, state)`
10. **注册 `tool_result` 监听**：`subagent` 工具返回时如有 async job，重渲染 widget 并启动 poller
11. **注册 `session_start`/`session_shutdown`**：前者绑定 session id 和 intercom 通道、设置 `PI_SUBAGENT_PARENT_SESSION`、恢复 active jobs；后者清理一切

### 1. 同步执行（foreground）

当用户请求走 `subagent` 工具且没有 `async: true`：

```
pi (parent)
  └─ tool.execute(subagent { agent, task, ... })
        └─ executeSubagentCollapsed()                       index.ts:395
              └─ executor.execute(id, params, signal, onUpdate, ctx)
                                                    subagent-executor.ts
                    ├─ reserveSubagentSpawns()      // 检查 session 内 spawn 上限
                    ├─ discoverAgents() / scope resolution
                    ├─ mode 判别:
                    │     ├─ action   → handleManagementAction()
                    │     ├─ view     → run-status inspection
                    │     ├─ chain    → executeChain()       (chain-execution.ts)
                    │     ├─ tasks    → runParallel()        (execution.ts)
                    │     └─ agent    → runSync() / runAsync()
                    ├─ control event bus 订阅
                    ├─ 子进程 fork：spawn(pi ...)            runs/shared/pi-args.ts
                    ├─ 订阅 nested events、events.jsonl
                    ├─ onUpdate() 把 partial result 推给 TUI
                    └─ 返回 AgentToolResult<Details>
```

`Details`（`src/shared/types.ts:516-552`）包含 `mode`、`results[]`、`controlEvents`、`progress`、`workflowGraph`、`outputs`、`totalCost`、`totalChildUsage` 等。

`runSync`（`runs/foreground/execution.ts`）对单个 agent：

1. 构造 `pi` CLI 参数（`buildPiArgs` in `runs/shared/pi-args.ts`），注入 system prompt、tools、extensions、intercom target、parent route、tool/turn budget、structured output 等
2. fork 子进程，stderr/stdout 经 JSONL writer 落到 `artifacts/<runId>/`
3. 监听子进程的 `events.jsonl`（nested events），实时回传 progress
4. 完成后返回 `SingleResult`

### 2. 异步执行（background）

`async: true` 时路径不同（`runs/background/async-execution.ts`）：

```
executor.execute()
  └─ buildAsyncRunnerSteps() / isAsyncAvailable()  // 检查 async 支持（execSync npm root）
        └─ executeAsyncSingle() / executeAsyncChain()
              ├─ 生成 runId、asyncDir = ~/.pi/agent/sessions/<sid>/async/<runId>/
              ├─ 写入 status.json、events.jsonl、metadata
              ├─ fork 子进程（detach）
              ├─ emit SUBAGENT_ASYNC_STARTED_EVENT（事件总线）
              ├─ async-job-tracker 启动轮询（POLL_INTERVAL_MS）
              └─ 父会话立即返回（带 asyncId/asyncDir 引用）
```

子代理完成后：

1. 写 `output.log`、`status.json`（`state: complete|failed|paused|stopped`）
2. 通过事件总线 `subagents:async:complete` 发完成事件
3. result-watcher（`fs.watch` + 轮询 fallback）捕获新文件
4. async-job-tracker 把事件转成 `subagent-notify` 自定义消息
5. Pi 把通知投递到父会话；如已完成，`restoreSlashFinalSnapshots` 把最终快照渲染回去
6. 父模型拿到通知后再决定下一步（如 `wait` 工具同步等待）

### 3. 控制通道（control channel）

子代理进程在跑的时候会向 `~/.pi/agent/sessions/<sid>/async/<runId>/events.jsonl` 写事件，事件总线 `subagents:control:event` 把这些事件传回父会话：

- `active_long_running`：跑了很久没停（默认 240s，可配）
- `needs_attention`：连续失败、idle 超时、超出 turn 阈值、token 阈值等

控制事件经 `extension/control-notices.ts` 渲染成框线高亮的 inline 通知，并在 `subagent.asyncJobs` 上挂起活动状态。父模型可通过 `subagent({ action: "interrupt" | "stop" | "resume" | "steer" | "append-step", id })` 干预：

- `interrupt`：软中断当前 child turn，run 进入 `paused`
- `stop`：硬停止（kill），run 进入 `stopped`
- `resume` + `message`：对 paused / 已结束的子代理投递 follow-up
- `steer`：在 live async child 上排队非终止性指导
- `append-step`：在 chain 尾部追加一个步骤（用 `{previous}` 拿最新输出）

### 4. 嵌套（nesting）

子代理里如果需要再调子代理（fanout），由 `extension/fanout-child.ts` 提供一个受限入口：

- 通过 `PI_SUBAGENT_FANOUT_CHILD=1` 触发
- 加载 `subagent-prompt-runtime.ts`、`fanout-child.ts` 作为额外 extension
- 使用 child-safe `subagent` 工具，受 `maxSubagentDepth`、`subagentSpawnsPerSession` 限制
- 父子之间通过 nested events 通信，父会读取 child 的 `events.jsonl` 并把事件 mirror 到自己的事件总线

### 5. Watchdog（可选）

`registerMainWatchdog(pi)` 在 `session_start` 时跑（`src/watchdog/register-main.ts`）：

- 监听 repo edits、buffered deltas
- 在 `agent_end` 边界汇总本回合实际改动的文件
- 跳过 `tmp/`、`.pi-subagents/`、未变更/被回滚的 diff
- 先用 LSP 拉诊断（`watchdog/lsp-diagnostics.ts`，自动探测 `typescript-language-server`）
- 然后调用配置模型做对抗性 review（`watchdog/review.ts`）
- 输出 `concern` / `blocker` 警告，附在回合末尾；严重时升级到 `needs_attention`

可通过 `subagent({ action: "watchdog.configure", ... })` 或 `/subagents-watchdog` 命令配置。

## 事件生命周期

Pi 的事件总线是这套系统的中枢：

| 事件常量 | 含义 | 文件 |
|----------|------|------|
| `SUBAGENT_ASYNC_STARTED_EVENT` (`subagents:async:started`) | 异步子代理已启动 | `shared/types.ts` |
| `SUBAGENT_ASYNC_COMPLETE_EVENT` (`subagents:async:complete`) | 异步子代理已完成 | `shared/types.ts` |
| `SUBAGENT_CONTROL_EVENT` (`subagents:control:event`) | 子代理发出 control 信号 | `shared/types.ts` |
| `SUBAGENT_RESULT_INTERCOM_EVENT` (`subagents:result:intercom`) | 结果通过 intercom 桥交付 | `shared/types.ts` |
| `SUBAGENT_RPC_REQUEST_EVENT` (`subagents:rpc:v1:request`) | 子进程请求父会话 RPC | `extension/rpc.ts:14` |
| `SUBAGENT_RPC_READY_EVENT` (`subagents:rpc:v1:ready`) | 父会话就绪，可接受 RPC | `extension/rpc.ts:15` |
| `SLASH_SUBAGENT_REQUEST_EVENT` (`subagents:slash:request`) | 斜杠命令请求执行 | `slash/slash-bridge.ts` |
| `SLASH_SUBAGENT_RESPONSE_EVENT` (`subagents:slash:response`) | 执行结果回给斜杠命令 | `slash/slash-bridge.ts` |

`registerSubagentExtension` 在末尾通过 `pi.events.on(...)` 集中订阅：

```ts
// src/extension/index.ts:561-567
const eventUnsubscribes = [
    pi.events.on(SUBAGENT_ASYNC_STARTED_EVENT, handleStarted),
    pi.events.on(SUBAGENT_ASYNC_COMPLETE_EVENT, handleComplete),
    pi.events.on(SUBAGENT_CONTROL_EVENT, controlEventHandler),
    rpcBridge.dispose,
];
```

`session_shutdown` 时统一 unsubscribe 并清理 timers、watchers、bridges。

## 目录与文件布局

子代理运行时落盘的目录约定（`shared/types.ts` 中的常量）：

| 路径常量 | 默认值 | 用途 |
|----------|--------|------|
| `TEMP_ROOT_DIR` | `<tmpdir>/pi-subagents-<scope>` | 子代理临时根 |
| `RESULTS_DIR` | 同上 + `/results` | 子代理结果文件（result-watcher 监听） |
| `ASYNC_DIR` | `~/.pi/agent/sessions/<sid>/async` | 异步运行根 |
| `CHAIN_RUNS_DIR` | `<TEMP_ROOT_DIR>/chain-runs` | 链式运行的 `chain_dir` |
| `agentDir` | `~/.pi/agent/` | 用户级配置（settings.json、subagent 配置、chains、extensions） |

子代理的输出 artifacts：

```
~/.pi/agent/sessions/<sid>/
  <sid>.jsonl                    # 父会话
  <sid>/
    async/<runId>/
      status.json                # 状态（state、activity、tokens、steps）
      events.jsonl               # 嵌套事件流
      output.log                 # 子代理 stdout
      artifacts/
        input.txt                # 输入快照
        output.txt               # 最终输出
        transcript.md            # Markdown 形式 transcript
        metadata.json            # 模型/工具/参数
        jsonl/                   # 完整消息流
    <runId>/                     # 链式运行的 chain_dir
      progress.md
      parallel-N/<idx>-<agent>/  # 并行步骤的子目录
        output.md
```

24 小时以上的旧 chain dir 会在 extension 启动时被 `cleanupOldChainDirs` 自动清理。

## 主要状态字段

`SubagentState`（`shared/types.ts`，被 `extension/index.ts:266-286` 实例化）维护扩展运行时状态：

- `baseCwd` / `currentSessionId` — 当前 session 上下文
- `subagentInProgress` / `subagentSpawns` — spawn 限额跟踪（per session）
- `asyncJobs: Map<asyncId, AsyncJobState>` — 异步 job 表
- `foregroundRuns` / `foregroundControls` — 前台运行的实时控制
- `pendingForegroundControlNotices` — 待渲染的控制通知
- `lastUiContext` — 最近一次 UI context，用于 slash / RPC bridge
- `poller` / `watcher` — 轮询和文件 watcher 的句柄
- `completionSeen` / `resultFileCoalescer` — 完成去重与文件 coalescer

扩展的"runtime cleanup"（`extension/index.ts:299-310`）负责释放这些资源；`session_shutdown` 时再次完整清理。
