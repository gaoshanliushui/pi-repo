# 存储布局与配置

本扩展把几乎所有持久状态都放在用户目录下（`~/.pi/workflows/`），避免给项目目录塞 `.pi/workflows/` 噪音。项目级状态按 cwd 哈希分桶。

## 1. 目录树

```
~/.pi/workflows/                                  ← workflowHomeDir()
├── settings.json                                 ← 全局设置
├── model-tiers.json                              ← tier → model 映射
├── saved/                                        ← 用户级已保存工作流
│   └── <name>.json
├── projects/                                     ← WORKFLOW_PROJECTS_SUBDIR
│   └── <slug>-<12字符hash>/                      ← 每个项目一个目录
│       ├── settings.json                         ← 项目级 settings 覆盖
│       ├── runs/                                 ← run 状态
│       │   ├── <runId>.json
│       │   ├── <runId>.json.bak
│       │   ├── <runId>.log
│       │   └── <runId>.lock
│       └── saved/                                ← 项目级已保存工作流
│           └── <name>.json
└── ...

<项目根>/.pi/workflows/                           ← LEGACY（只读兼容）
├── runs/                                         ← 老 run 数据
└── saved/                                        ← 老 saved 数据
```

`workflowProjectPaths(cwd)` 返回的 `key` 是 `<sanitized basename>-<12字符 sha256(absolute cwd)>` 形如 `my-app-7b3a91f0c2d4`。

## 2. `settings.json`

位置：`~/.pi/workflows/settings.json`（项目级：`~/.pi/workflows/projects/<key>/settings.json`）。

加载时合并顺序：项目级覆盖全局。`saveWorkflowSettingsForCwd` 会同时写全局与项目级。

```json
{
  "keywordTriggerEnabled": true,
  "keywordTriggerWord": "pi-workflow",
  "defaultAgentTimeoutMs": 600000,
  "defaultConcurrency": 4,
  "defaultAgentRetries": 2,
  "progressPanelMode": "detailed",
  "progressPanelMaxAgents": 12,
  "persistAgentSessions": true,
  "deliveredResultMaxChars": 800
}
```

| 字段 | 类型 / 默认 | 说明 |
| --- | --- | --- |
| `keywordTriggerEnabled` | `boolean` | 是否启用输入框里"打 workflow 触发" |
| `keywordTriggerWord` | `string` | 自定义关键字（默认 `"workflow"`）；`normalizeKeywordTriggerWord` 拒绝带空格或 `/` 前缀 |
| `defaultAgentTimeoutMs` | `number \| null` | 全局默认每个 agent 的硬超时；`null` = 不限时 |
| `defaultConcurrency` | `1..16` | 全局默认并发上限 |
| `defaultAgentRetries` | `0..3` | 全局默认重试次数 |
| `progressPanelMode` | `"compact" \| "detailed"` | 任务面板一行还是带 per-agent tok/s 的详细模式 |
| `progressPanelMaxAgents` | `1..1000` | detailed 模式下每 phase 显示多少 agent |
| `persistAgentSessions` | `boolean` | 子代理 transcript 是否落盘为 Pi 会话（keyed by 项目 cwd） |
| `deliveredResultMaxChars` | `1..1_000_000` | 后台 run 回投结果的 JSON dump 截断阈值 |

对应类型定义：`src/workflow-settings.ts` 的 `WorkflowSettings`。

## 3. `model-tiers.json`

位置：`~/.pi/workflows/model-tiers.json`。

```json
{
  "tiers": {
    "small": "openai-codex/gpt-5.4-mini:low",
    "medium": "openai-codex/gpt-5.4:medium",
    "big": "openai-codex/gpt-5.5:xhigh"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `tiers` | `Record<string, string>`，每个值是 `provider/modelId[:thinking]` |
| 未配置 | `buildDefaultTierConfig` 拉取 `ModelRegistry.getAvailable()`，按 `SMALL_MODEL_HINTS`（mini/flash/haiku/nano/small）与 `BIG_MODEL_HINTS`（opus/pro/ultra/large/plus）打分排序，1 个最强+1 个最弱分配 small/big，3+ 个时中间分给 medium；2 个时 stronger 覆盖 medium+big；1 个时所有 tier 都是它 |
| 临时覆盖 | `WorkflowAgentOptions.session.model` 不会被 tier 解析影响（明确优先级见 [script-api.md](./script-api.md)） |
| 思考等级 | 用 `:thinking` 后缀，例如 `:xhigh`、`:medium`、`:max` |

用 `/workflows-models` 命令在 TUI 里编辑（`workflows-models-command.ts`）。底层 schema 与 `parseModelRoutingFromMeta` 的 `meta.phases[].model` 共用——都可以包含 `provider/modelId:thinking`。

## 4. 持久化 run 状态

`RunPersistence.save(state)` 写盘内容（节选）：

```json
{
  "runId": "auth_audit-lpx7",
  "workflowName": "auth_audit",
  "script": "export const meta = { ... }\n...",
  "args": { "scope": "src/routes" },
  "sessionId": "abc-123",
  "status": "running",
  "phases": ["Scan", "Review", "Verify"],
  "currentPhase": "Review",
  "agents": [
    {
      "id": 1,
      "label": "route inventory",
      "phase": "Scan",
      "prompt": "...",
      "status": "done",
      "resultPreview": "src/routes/a.ts\nsrc/routes/b.ts",
      "tokens": 1823,
      "model": "anthropic/claude-fable-5",
      "startedAt": "2026-07-14T10:11:13.000Z",
      "endedAt": "2026-07-14T10:11:18.421Z"
    }
  ],
  "logs": ["[ts] [INFO] ..."],
  "tokenUsage": {
    "input": 12340,
    "output": 5021,
    "total": 17361,
    "cost": 0.0431,
    "cacheRead": 8000,
    "cacheWrite": 1200
  },
  "journal": [
    { "index": 0, "hash": "<sha256>", "result": "..." },
    { "index": 1, "hash": "<sha256>", "result": "...", "storeDelta": { "k": "v" } }
  ],
  "startedAt": "2026-07-14T10:11:12.000Z",
  "updatedAt": "2026-07-14T10:11:18.421Z",
  "durationMs": 6421
}
```

字段含义：

| 字段 | 说明 |
| --- | --- |
| `status` | `pending` / `running` / `paused` / `completed` / `failed` / `aborted` |
| `pauseReason` | `"usage_limit"`（PROVIDER_USAGE_LIMIT 触发） |
| `resetHint` | 提供商的 reset 提示文本（如 "Resets in ~3h"） |
| `agents` | 每次 agent 完成的快照（id/label/phase/prompt/status/resultPreview/error/tokens/model） |
| `logs` | 完整日志 |
| `journal` | resume 用的"按 callIndex 的结果账本" |
| `journal[].storeDelta` | 该 agent 写过的 store 增量（resume 时按 callSeq 顺序 applyDelta） |

### 4.1 原子写与备份

```ts
writeFileSync(`${path}.tmp`, json)
renameSync(`${path}.tmp`, path)        // 原子
writeFileSync(`${path}.bak`, json)     // 兜底
```

`load(runId)` 按 primary → primary.bak → legacy primary → legacy primary.bak 顺序尝试解析，损坏文件自动跳过。

### 4.2 跨进程锁

`<runId>.lock` 形如：

```json
{ "runId": "...", "runPath": "...", "pid": 48211, "startedAt": "...", "token": "..." }
```

`acquireRunLease`：

1. 用 `wx` flag（O_EXCL）原子创建。
2. EEXIST → 读现有锁的 pid，`process.kill(pid, 0)` 探测；存活 → 锁被他人持有，返回 `null`；死亡 → 删旧锁重试。
3. 重试 2 次都失败返回 `null`。

`releaseRunLease` 校验 token 匹配后 unlink。token 不匹配说明锁已经被替换/借走，不动它。

### 4.3 启动时的孤儿恢复

`new WorkflowManager` 时 `recoverStaleRuns()` 遍历所有 `running` 的持久 run：抢到锁（说明原进程已死）就改成 `paused`，绝不改成 `failed`——失败状态会让用户失去账本。

## 5. 命名子代理（`agentType`）

位置（按优先级）：

1. `<项目根>/.pi/agents/*.md`（项目级，cwd 相对）
2. `~/.pi/agent/agents/*.md`（用户级，遵循 pi-coding-agent 的 `getAgentDir()`，也支持 `PI_CODING_AGENT_DIR` 环境变量）
3. `~/.pi/agents/*.md`（**deprecated**，只读兼容，会打一次警告）

文件格式（YAML frontmatter + Markdown body）：

```markdown
---
name: security-auditor
description: Audits code for security issues
tools: [read, grep, glob]
disallowedTools: [bash]
model: anthropic/claude-fable-5
isolation: worktree
---

You are a security auditor. Focus on authn, authz, injection, and secrets handling.
```

加载规则：项目 → 用户 → 旧用户，先来先得（同名时只保留第一个）。`agentDefinitionKey(def)` 序列化关键字段进 callHash，因此编辑 `.md` 后 resume 会重新跑对应 agent。

## 6. 已保存工作流

`/workflows save <name>` 把最近一次 run 的脚本保存为 `SavedWorkflow`：

```json
{
  "name": "code-review",
  "description": "...",
  "script": "export const meta = { ... }",
  "parameters": {
    "scope": { "type": "string", "required": true },
    "minScore": { "type": "number", "default": 0.5 }
  },
  "location": "user",
  "path": "/home/me/.pi/workflows/saved/code-review.json",
  "savedAt": "2026-07-14T10:00:00.000Z"
}
```

存储位置（按优先级）：

1. `<项目>/.pi/workflows/saved/<name>.json` —— 项目级
2. `<项目>/.pi/workflows/saved/<name>.json` (legacy) —— 老位置
3. `~/.pi/workflows/saved/<name>.json` —— 用户级

`registerAllSavedWorkflows` 把它们都注册为 `/<name>` 命令，参数解析用 `parseCommandArgs`：`key=value` 进对象，其余进 `args._` 与 `args._raw`，再用 `parameters` 里的 `default` 补缺。

## 7. 任务面板与回投

- `installTaskPanel`：把 `manager` 的 `agentStart / agentEnd / log / phase / tokenUsage / complete / error` 桥接到 ctx.ui 的 widget，位置在输入框下方。
- `installResultDelivery`：run 完成后用 `pi.sendMessage({ customType, content, display: true })` 回投到聊天，content 优先取 `result.report / result.verdict / result.summary`，否则对 `result` 做 JSON dump 并按 `deliveredResultMaxChars` 截断，丢失的部分以 `…(truncated N KB)` 显示。

## 8. 迁移

`workflowProjectPaths(cwd)` 同时返回 `runsDir` 与 `legacyRunsDir`、`savedDir` 与 `legacySavedDir`。`RunPersistence` / `WorkflowStorage` 在读时尝试 legacy，写时只写新位置，确保老数据被平滑迁移。

`agent-registry.ts` 的 `loadAgentRegistry` 同样读三个目录（旧用户级打一次 warning 后不再 warn）。

## 9. 子代理 session（可选）

当 `persistAgentSessions: true`：

- 子代理走 `SessionManager.create(this.cwd)`（不是 `inMemory()`），会写到 `~/.pi/agent/sessions/<encoded-cwd>/<sid>.json`。
- 命名 `workflow:<runId> <label>`，所以在 `/resume` 等 session 选择器里能识别。
- `assertSessionDirWritable` 探测目录可写性，失败时静默回退 in-memory（绝不因 fs 错误 abort run）。
- 注意：与 run JSON 不同，session transcript 是**完整**未截断的——任何被子代理读入上下文的内容（包括 secrets）都会落盘。
- key 用 `this.cwd`（runner 的项目 cwd）而非 worktree cwd，所以同一项目的所有 run 在一个 session 目录里。
