# Resource Loader

`packages/coding-agent/src/core/resource-loader.ts` 是 coding-agent 会话启动阶段的资源发现与装配中枢。它把散落在用户目录 (`agentDir`)、工作目录 (`cwd/.pi`)、命令行临时参数、CLI 内联工厂以及第三方 package 中的扩展/技能/提示模板/主题/上下文文件收拢成一个统一的、带来源元信息的资源视图，供 `AgentSession`、TUI、内置工具及扩展 hook 使用。

## 主要完成的工作

- **上下文文件加载**：`loadProjectContextFiles` 从 `agentDir` 与 `cwd` 沿目录向上，逐级查找 `AGENTS.md`/`CLAUDE.md`（大小写变体各两种），去重后按 "全局 → 从祖先到当前目录" 顺序返回，形成模型的项目上下文。
- **扩展加载与合并**：读取 `PackageManager` 解析出的启用扩展路径，与 CLI 临时扩展 (`additionalExtensionPaths`) 合并，交由 `loadExtensionsCached` 装载；同时执行内联 `extensionFactories` (`loadExtensionFactories`) 得到 `<inline:name>` 形态的扩展并追加到结果里。
- **信任双阶段加载**：当调用方提供 `resolveProjectTrust` 时，先在“项目不信任”的状态下加载一次扩展 (`loadProjectTrustExtensions`)，交给上层决定是否给项目授信；随后按最终信任态刷新 `SettingsManager`，用 `loadFinalExtensionSet` 复用第一次已成功的扩展、只补跑剩余路径，避免重复初始化。
- **冲突诊断**：`detectExtensionConflicts` 遍历扩展间同名 tool / flag，将冲突落到 `LoadExtensionsResult.errors`，扩展本身仍保留，按加载顺序决定优先级。
- **技能装载**：`updateSkillsFromPaths` 调 `loadSkills`；对 `source==auto` 或 `origin==package` 且目录内存在 `SKILL.md` 的资源，由 `mapSkillPath` 定位到具体的 `SKILL.md` 文件路径。
- **提示模板装载与去重**：`updatePromptsFromPaths` 通过 `loadPromptTemplates` 收集全部模板，然后按 `name` 首个胜出去重，未胜者以 `type: collision` 诊断记录冲突文件路径。
- **主题装载与去重**：`loadThemes` 支持传入目录或 `.json` 文件、遍历符号链接，`dedupeThemes` 按 `name` 保留首个，冲突同样以 collision 诊断报告。
- **系统提示解析**：`resolvePromptInput` 允许 `systemPrompt`/`appendSystemPrompt` 既接文件路径又接原始字符串；未显式指定时用 `discoverSystemPromptFile` / `discoverAppendSystemPromptFile`，按“项目 `.pi/SYSTEM.md`（需信任） → 全局 `agentDir/SYSTEM.md`”优先顺序发现。
- **来源信息 (SourceInfo)**：`applyExtensionSourceInfo`、`findSourceInfoForPath`、`getDefaultSourceInfoForPath` 为每个 extension/skill/prompt/theme 附加 `source/scope/origin/baseDir` 元数据，把 CLI 临时项、包内资源、user/project 目录下的本地资源清晰区分开，供 TUI 及诊断输出使用。
- **可覆盖的注入点**：构造参数暴露 `extensionsOverride`、`skillsOverride`、`promptsOverride`、`themesOverride`、`agentsFilesOverride`、`systemPromptOverride`、`appendSystemPromptOverride`，SDK 消费者可以在最终值敲定前追加、过滤或重写任一类资源。
- **诊断**：非致命问题（路径不存在、theme 不是 json、冲突等）统一走 `ResourceDiagnostic`（`error`/`warning`/`collision`），不打断加载。
- **动态扩展**：`extendResources` 允许在扩展 hook 首次执行后新增技能/模板/主题路径，合并到 `lastSkillPaths` 等缓存并局部刷新对应视图，无需整体 `reload`。

## 加载流程

`DefaultResourceLoader.reload(options)` 是主入口。典型时序：

1. **重置计时与缓存**：`resetTimings("extensions")`；若不是首次加载，`clearExtensionCache()` 清掉 extension 模块级缓存。
2. **信任预扫描（可选）**：若传入 `resolveProjectTrust`
   - `loadProjectTrustExtensions` 将 `SettingsManager.projectTrusted = false`，重载设置；
   - 调 `loadCurrentExtensionSet({ includeInlineFactories: true })`，得到只含 user/global + CLI + inline 的 `preTrustExtensions`；
   - 交由调用方判定是否信任项目，`SettingsManager.setProjectTrusted(...)` 应用结果。
3. **重载设置与解析路径**：`settingsManager.reload()`，随后 `packageManager.resolve()` 得到 `.extensions/.skills/.prompts/.themes` 四类 `ResolvedResource[]`；`resolveExtensionSources(additionalExtensionPaths, { temporary: true })` 处理 CLI 层临时资源。
4. **收集元数据**：`getEnabledResources` 把每条资源的 `PathMetadata` 塞进 `metadataByPath`，同时挑出 `enabled=true` 的路径；CLI 资源以 `{ source: "cli", scope: "temporary", origin: "top-level" }` 补齐元信息。
5. **加载最终扩展集**：`loadFinalExtensionSet(extensionPaths, preTrustExtensions)`
   - 无预扫描：直接 `loadExtensionsCached` + inline 工厂 + 冲突诊断；
   - 有预扫描：从 `preTrustExtensions.extensions` 提取按 `resolvedPath` 索引的已加载项，剔除之前失败或已加载的路径，只对剩余路径复用 `runtime` 再跑 `loadExtensionsCached`；随后按用户提供的 `extensionPaths` 顺序重排，附加 `<inline:...>` 项与两次的 errors，再跑冲突诊断。
6. **补充失效路径警告**：遍历 `additionalExtensionPaths`，本地路径不存在时向 `errors` 追加 `Extension path does not exist`。
7. **合并各类资源路径**：
   - 技能：`cliEnabledSkills + enabledSkills(可选被 noSkills 屏蔽) + additionalSkillPaths`；
   - 模板/主题同构，均由 `mergePaths` 使用 `canonicalizePath` 去重并把相对路径解析到 `cwd`；
   - 分别调用 `updateSkillsFromPaths`、`updatePromptsFromPaths`、`updateThemesFromPaths` 刷新缓存；
   - 每类都再遍历一次 `additional*Paths`，本地路径缺失时追加相应 diagnostic。
8. **应用 override & 补充 sourceInfo**：`applyExtensionSourceInfo` 给扩展、扩展的 command/tool 补 `sourceInfo`；每次 `update*FromPaths` 内部通过 `findSourceInfoForPath` 优先匹配 `extensionSkillSourceInfos` 等 extension 注入表，再回退到 `metadataByPath`，最后回退到 `getDefaultSourceInfoForPath`（按 agentDir 与 `cwd/.pi` 子目录归类为 user/project scope，其他归为 temporary）。
9. **项目上下文文件**：若非 `noContextFiles`，调用 `loadProjectContextFiles({ cwd, agentDir })` 收集 `AGENTS.md`/`CLAUDE.md`，再走 `agentsFilesOverride`。
10. **系统提示 & append 系统提示**：
    - `systemPrompt`：优先 `systemPromptSource`，否则 `discoverSystemPromptFile`；经 `resolvePromptInput` 支持“存在即读文件、否则原样字符串”，再走 `systemPromptOverride`。
    - `appendSystemPrompt`：来源同构，为数组；`resolvePromptInput` 分别处理每一项，`undefined` 过滤后交给 `appendSystemPromptOverride`。
11. **标记完成**：`this.loaded = true`；之后再次调用 `reload` 会先清 extension 缓存以确保读取到最新代码。

## 对外只读接口

| 方法 | 返回 |
| ---- | ---- |
| `getExtensions()` | `LoadExtensionsResult`：extensions、errors、runtime |
| `getSkills()` | `{ skills, diagnostics }` |
| `getPrompts()` | `{ prompts, diagnostics }` |
| `getThemes()` | `{ themes, diagnostics }` |
| `getAgentsFiles()` | `{ agentsFiles: Array<{ path, content }> }` |
| `getSystemPrompt()` | `string | undefined` |
| `getAppendSystemPrompt()` | `string[]` |
| `extendResources(paths)` | 动态扩展 skill/prompt/theme 路径并局部刷新 |
| `reload(options)` | 触发上述完整流程 |

## 与其他模块的关系

- **`SettingsManager`**：控制项目信任态、启用/禁用清单；`reload` 期间会被切换并重载。
- **`DefaultPackageManager`**：负责把 `.pi` 目录、package 依赖、CLI 临时路径解析成 `ResolvedResource`，并附带 `PathMetadata`（source/scope/origin/enabled/baseDir 等）。
- **`extensions/loader.ts`**：真正加载扩展模块，`loadExtensionsCached` 支持在给定 runtime 上并行装载；`loadExtensionFromFactory` 支持 SDK 传入的内联工厂。
- **`skills.ts` / `prompt-templates.ts` / `modes/interactive/theme/theme.ts`**：单独负责各自资源的文件解析。
- **`source-info.ts`**：把 `PathMetadata` 转成 UI/诊断可展示的 `SourceInfo`。
- **`diagnostics.ts`**：`ResourceDiagnostic` 类型统一了 error/warning/collision 的表达。

## 常见调用方式

- 一次性 headless 场景：构造 `DefaultResourceLoader({ cwd, agentDir, ... })`，`await loader.reload()`，随后消费只读 getter。
- 交互式 CLI：`await loader.reload({ resolveProjectTrust })`，UI 层根据 `preTrustExtensions` 弹出授信提示后返回 boolean。
- SDK/嵌入式：通过 `extensionFactories` 注入内联扩展、通过各类 `*Override` 精修输出、通过 `extendResources` 在运行时挂载新技能/模板/主题。
